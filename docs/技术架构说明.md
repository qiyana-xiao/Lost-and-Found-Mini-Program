# 校园失物招领站 — 技术架构说明

> 适用范围：开发者快速理解本项目结构、前后端分工、以及"本地模式 ↔ 云端模式"的双轨设计。
> 最后更新：2026-09-30

---

## 一、项目定位与技术栈

| 项 | 内容 |
|---|---|
| 形态 | 微信小程序（原生开发，未使用框架） |
| 语言 | TypeScript（编译为小程序 JS）+ WXML + WXSS |
| 前端 | 微信小程序基础库 API（`wx.*`） |
| 后端（可选） | 微信云开发：云函数（`wx-server-sdk`）+ 云数据库 + 云存储 |
| 当前运行模式 | **本地存储模式**：数据存 `wx.storage`，图片存本机文件目录，**零云服务依赖，开箱即跑** |
| 预留云端模式 | `cloudfunctions/` 已含 7 个云函数源码，与 `db.ts` 接口一一对应，切换即可上云 |

## 三、前端架构

### 3.1 分层设计（核心思想：页面不直连存储）

```
页面层 (pages/*)  ──只调用──▶  utils/db.ts  ──▶  本地(wx.storage)  /  云端(wx.cloud.callFunction)
                    └──调用──▶  utils/auth.ts ──▶  本地账号缓存
                    └──调用──▶  utils/upload.ts ──▶ 本地文件 / 云存储
                    └──调用──▶  utils/util.ts ──▶  纯函数工具
```

- **页面层**：负责 UI 与交互，所有数据一律通过 `db.ts` 暴露的函数获取/写入，**不直接 `wx.getStorageSync` 或 `wx.request`**。
- **数据层 (`db.ts`)**：唯一的数据访问边界。当前为本地实现；上云时只需替换其内部实现，页面零改动。
- **身份层 (`auth.ts`)**：登录态唯一来源，提供 `getUid()` / `getUser()` / `login()` / `register()` / `logout()`。
- **图片层 (`upload.ts`)**：`uploadImage` 统一处理压缩与保存，页面不碰文件系统。
- **工具层 (`util.ts`)**：分类枚举 `CATEGORIES`、emoji 映射、联系方式脱敏 `maskContact`、相对时间 `formatRelative`。

### 3.2 数据模型

**条目 items（本地以数组存于 `wx.storage['lost_found_items']`）**
```
{ _id, _openid, type('lost'|'found'), title, category, location,
  happenTime, description, images:[path], contact, status('open'|'closed'),
  views, createdAt, updatedAt }
```

**留言 messages（本地 `wx.storage['lost_found_messages']`）**
```
{ _id, itemId, _openid, content, contact, createdAt }
```

**本机账号 users（`wx.storage['lost_found_local_users']`）**
```
{ username, password, nickname, avatar }
```

**已读记录 readMap（`wx.storage['lost_found_read_<uid>']`）**：`{ [itemId]: 已读时间戳 }`，用于消息未读计算。

### 3.3 页面职责

| 页面 | 关键交互 | 依赖 |
|---|---|---|
| index | 列表、筛选 Tab、分类、分页、下拉刷新 | db.getList / db.getStats |
| search | 关键词 + 分类检索 | db.getList |
| publish | 表单、图片（最多3）、草稿、编辑模式 | db.addItem / upload.uploadImage |
| detail | 展示、留言、认领、浏览量自增 | db.getDetail / db.addMessage / db.closeItem |
| mine | 个人中心、我的发布、统计 | db.getList(mine) / db.getStats / db.deleteItem |
| messages | 消息聚合、未读、全部已读 | db.getMessageList / db.markItemRead / db.markAllRead |
| login | 登录 / 注册 | auth.* |

### 3.4 状态与刷新

- 列表页在 `onShow` 重新拉数据（保证从详情/发布返回后刷新）。
- 未读角标：每次进入 `mine` / `messages` 调用 `db.refreshMsgBadge()`，更新 tabBar 角标（当前角标挂在"消息" tab，索引 1）。
- 登录态变化：登录/注册/退出后调用 `auth.afterLogin()` → 重新 `seedDemo` 并刷新当前页。

## 四、后端 / 云端架构（预留）

> 当前默认未启用；代码已实现，按《上架微信云平台操作手册》切换即可。

### 4.1 云函数（7 个）

| 云函数 | 入参 | 行为 | 返回 |
|---|---|---|---|
| addItem | item 字段 | 写入 `items`，`_openid`=调用方 | 新 `_id` |
| addMessage | {itemId, content, contact} | 写入 `messages`，1 分钟≤3 条限流 | 新 `_id` |
| getList | {keyword, type, category, page, pageSize} | 标题正则 + 类型/分类筛选 + 分页 | {data, page, total} |
| getDetail | {id} | 取条目 + 该条目留言 | {data, messages} |
| incrementView | {id} | `views+1` | — |
| closeItem | {id} | 校验归属后 `status='closed'` | — |
| deleteItem | {id} | 校验归属后删条目 + 级联删留言 | — |

云函数通过 `wx-server-sdk` 操作云数据库，天然携带 `openid`（调用方身份），权限校验在云函数内完成（归属检查）。

### 4.2 云数据库集合

- `items`：条目集合。权限建议设为 **自定义**：所有人可读、仅创建者可写。
- `messages`：留言集合。建议 **自定义**：所有人可读、仅创建者可写（写入时自动带 openid）。
- 云端不再需要本机的 `readMap` / `users` 存储；已读时间戳可另建集合（见操作手册）。

### 4.3 云存储

- 发布图片经 `upload.uploadImage` → `wx.cloud.uploadFile` 上传，存于云存储，返回 `cloud://` 路径，可跨用户、跨设备访问。

## 五、双运行模式设计（本地 ↔ 云端）

```
                 ┌─────────────── db.ts ───────────────┐
                 │  getList / addItem / addMessage ...   │
                 └────────────────┬─────────────────────┘
                                  │
            ┌─────────────────────┴─────────────────────┐
            │               运行模式开关                   │
            ▼                                            ▼
   本地模式（默认）                              云端模式（上云后）
   wx.storage 读写                               wx.cloud.callFunction
   本机图片保存                                 wx.cloud.uploadFile
   本机账号(auth)                               微信 openid
```

- **切换点**：仅 3 处——`app.ts`（环境初始化 + 是否 seedDemo）、`db.ts`（内部实现）、`upload.ts`（图片处理）。
- **页面层零改动**：因接口签名稳定，切换后端对页面透明。
- **降级思路**：云端模式下可保留本地缓存作为列表缓存，弱网时降级展示；当前本地模式即为完整的离线降级态。

## 六、关键数据流

### 6.1 发布
`publish.ts` → 校验 → `upload.uploadImage(逐张)` → `db.addItem({...})`（写入 images 数组）→ 返回列表。

### 6.2 浏览
`index.ts`(`onShow`) → `db.getList({type,category,page})` → 卡片渲染；点击 → `detail.ts` → `db.getDetail` + `db.incrementView`。

### 6.3 留言 → 消息
`detail.ts` → 非发布者填表单 → `db.addMessage` → 写入 `messages`（带 `_openid`=留言者）；`db.refreshMsgBadge()` 刷新消息角标；发布者在 `messages` 页 `db.getMessageList` 看到聚合留言，点击 `markItemRead` 进详情并消未读。

### 6.4 认领
`detail.ts`（发布者）→ `db.closeItem` → `status='closed'` → 列表/详情同步状态。

## 七、安全与限流现状

| 维度 | 本地模式 | 云端模式（云函数已实现） |
|---|---|---|
| 归属校验 | 前端判断 `_openid`，可被绕过 | 云函数内 `openid` 校验，安全 |
| 留言限流 | 无 | addMessage 1 分钟≤3 条 |
| 内容安全 | 无 | 未接入（需内容安全 API） |
| 联系方式 | 脱敏展示，复制明文 | 同左 |

## 八、构建与运行

1. 用微信开发者工具打开项目根目录（`project.config.json` 已配置 `miniprogramRoot` / `cloudfunctionRoot`）。
2. 默认即本地模式，编译即可运行，**无需任何云服务配置**。
3. 若要启用云端：见《上架微信云平台操作手册》。

## 九、扩展与改造约定

- 新增数据操作 → 在 `db.ts` 暴露函数，页面只调 `db.*`。
- 登录态 → 统一 `auth.ts`。
- 图片 → 统一 `upload.ts`。
- 分类 / 常量 → 放 `util.ts`，避免散落。
- 切换本地/云端 → 只动 `app.ts` / `db.ts` / `upload.ts` 三处。
