# 上架微信云平台操作手册（本地 → 云开发 + 实时交互）

> **阅读对象**：执行改造的开发者（含未来的自己）。本手册以"施工单"形式给出每一步的**具体文件、具体位置、具体改动代码**，照做即可把当前"本地存储模式"切换为"微信云开发模式"，实现多用户真实跨设备共享数据 + 实时交互，并成功上架。
> 最后更新：2026-09-30
> 关联文档：《技术架构说明》《功能说明与优化规划》

## 〇、目标与原理（先看这段，避免改错方向）

当前项目是 **本地存储模式**：`db.ts` 直接读写 `wx.storage`，`upload.ts` 把图片存本机。所以**换设备看不到彼此数据**。

切换思路（架构已为此设计好）：
- 前端页面**只调用 `db.ts` / `upload.ts` 的函数**，不直接碰存储 → 上云时只替换这两个文件内部实现 + `app.ts` 初始化，**页面层零改动**。
- `cloudfunctions/` 里已写好 7 个云函数，接口签名与 `db.ts` 一一对应 → 直接部署即用。
- 云端身份用 **微信 `openid`**（自动、真实、跨设备），取代本地 `auth.username` 作为数据归属标识。
- 实时交互用 **云数据库 `watch`**（监听 `items` / `messages` 集合变更，前端即时刷新列表/消息）。

**改动总览（只动这几处）**：
| 改动 | 文件 | 性质 |
|---|---|---|
| A | `miniprogram/app.ts` | 初始化 `wx.cloud`、关闭本地 seedDemo |
| B | `miniprogram/utils/db.ts` | 内部实现改为调云函数 + 新增 watch 函数 |
| C | `miniprogram/utils/upload.ts` | 改为 `wx.cloud.uploadFile` |
| D | `miniprogram/pages/index/index.ts` | 注册 `watchItems` 实时刷新 |
| E | `miniprogram/pages/messages/messages.ts` | 注册 `watchMessages` 实时刷新 |
| F | 新增云函数 `getMyMessages`、`markRead` | 云端算未读/聚合、写已读 |
| G | 控制台操作 | 开通环境、建集合、部署云函数 |
| H | 发布上线 | 上传 → 审核 → 发布 |

## 一、前置条件与控制台准备（G）

1. 在 `https://mp.weixin.qq.com` 拥有已注册的小程序，拿到 **AppID**（当前 `project.config.json` 里是 `wxde33bc96c7c66463`，请确认这是你自己的 AppID，否则替换）。
2. 打开微信开发者工具，导入项目根目录（已识别 `miniprogramRoot` / `cloudfunctionRoot`）。
3. 顶部点 **"云开发"** → 开通 → 新建环境，记下 **环境 ID**（形如 `cloud1-xxxxxxxxxxxx`。
4. 在云开发控制台 **"数据库"** 新建两个集合，并设置权限：
   - 集合 `items`：权限选 **"自定义安全规则"** → 所有人可读、仅创建者可读写。
     ```json
     {
       "read": true,
       "write": "doc._openid == auth.openid"
     }
     ```
   - 集合 `messages`：同样自定义 → 所有人可读、仅创建者可读写（写入时自动带 openid）。
     ```json
     {
       "read": true,
       "write": "doc._openid == auth.openid"
     }
     ```
   - 集合 `read_log`（新增，存已读时间戳）：自定义 → 仅本人可读写。
     ```json
     {
       "read": "doc._openid == auth.openid",
       "write": "doc._openid == auth.openid"
     }
     ```
5. （可选）导入演示数据：把本地 `wx.storage['lost_found_items']` 的内容（开发者工具 → 调试器 → Storage 面板导出）整理成 JSON 批量导入 `items`，便于上线即见内容。

## 二、部署云函数（G + F）

1. **现有 7 个云函数**：`addItem / addMessage / getList / getDetail / incrementView / closeItem / deleteItem`。
   - 在开发者工具左侧"云函数"根目录逐个右键 → **"上传并部署：云端安装依赖（不上传 node_modules）"**。
   - 注意每个函数 `package.json` 已含 `wx-server-sdk`，云端会自动安装。
   - ⚠️ `getList` 已支持 `mine` 参数（云函数内用 `OPENID` 过滤"我的发布"），无需改。
   - ⚠️ `addItem / addMessage` 云函数内用 `cloud.getWXContext().OPENID` 作为真实 `_openid`，**不要**从前端传 uid。
2. **新增 2 个云函数**（在 `cloudfunctions/` 下新建文件夹 `getMyMessages` 和 `markRead`，各含 `index.js` + `package.json`）。

   **`cloudfunctions/getMyMessages/index.js`**（一次性算好"我的消息"聚合 + 未读）：
   ```js
   const cloud = require('wx-server-sdk')
   cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV })
   const db = cloud.database()
   const _ = db.command

   exports.main = async (event, context) => {
     const { OPENID } = cloud.getWXContext()
     const items = await db.collection('items').where({ _openid: OPENID }).get()
     if (!items.data.length) return { groups: [], total: 0, unread: 0 }
     const ids = items.data.map(i => i._id)
     const msgs = await db.collection('messages')
       .where({ itemId: _.in(ids) })
       .orderBy('createdAt', 'asc').get()
     const readRes = await db.collection('read_log').where({ _openid: OPENID }).get()
     const readMap = {}
     readRes.data.forEach(r => { readMap[r.itemId] = r.readAt })

     const groups = items.data.map(it => {
       const list = msgs.data.filter(m => m.itemId === it._id)
       const unread = list.filter(m => (m.createdAt || 0) > (readMap[it._id] || 0))
       const latest = list[list.length - 1]
       return {
         itemId: it._id,
         title: it.title || '未命名条目',
         count: list.length,
         unreadCount: unread.length,
         latestTime: latest ? (latest.createdAt || 0) : 0,
         latestContent: latest ? (latest.content || '') : '',
         latestContact: latest ? (latest.contact || '') : '',
       }
     }).filter(g => g.count > 0)
     groups.sort((a, b) => b.latestTime - a.latestTime)
     const unread = groups.reduce((s, g) => s + g.unreadCount, 0)
     const total = groups.reduce((s, g) => s + g.count, 0)
     return { groups, total, unread }
   }
   ```

   **`cloudfunctions/markRead/index.js`**（标记已读，写 read_log）：
   ```js
   const cloud = require('wx-server-sdk')
   cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV })
   const db = cloud.database()
   const _ = db.command

   exports.main = async (event, context) => {
     const { OPENID } = cloud.getWXContext()
     const now = Date.now()
     if (event.all) {
       const items = await db.collection('items').where({ _openid: OPENID }).get()
       for (const it of items.data) {
         await db.collection('read_log').where({ _openid: OPENID, itemId: it._id })
           .limit(1).get().then(async r => {
             if (r.data.length) {
               await db.collection('read_log').doc(r.data[0]._id).update({ data: { readAt: now } })
             } else {
               await db.collection('read_log').add({ data: { _openid: OPENID, itemId: it._id, readAt: now } })
             }
           })
       }
       return { ok: true }
     }
     const { itemId } = event
     const r = await db.collection('read_log').where({ _openid: OPENID, itemId }).limit(1).get()
     if (r.data.length) {
       await db.collection('read_log').doc(r.data[0]._id).update({ data: { readAt: now } })
     } else {
       await db.collection('read_log').add({ data: { _openid: OPENID, itemId, readAt: now } })
     }
     return { ok: true }
   }
   ```
   两个函数 `package.json` 与现有云函数一致：
   ```json
   { "name": "...", "version": "1.0.0", "dependencies": { "wx-server-sdk": "latest" } }
   ```
   新建后同样右键 **"上传并部署：云端安装依赖"**。

## 四、修改 miniprogram/utils/db.ts（B，核心）

**位置**：整个文件。把本地实现整体替换为"云端实现"，**保持对外函数签名不变**（页面依赖的 14 个函数名与入参不变）。

### 4.1 顶部常量与辅助
```ts
// 环境 ID，与 app.ts 保持一致（也可在此统一改为你自己的）
const ENV = 'cloud1-xxxxxxxx'

// 统一调用云函数
function call(name: string, data: any = {}): Promise<any> {
  return new Promise((resolve, reject) => {
    wx.cloud.callFunction({
      name, data,
      success: (res: any) => resolve(res.result),
      fail: (err) => reject(err),
    })
  })
}

// 统一访问云数据库（供 watch 用）
function cdb() {
  return wx.cloud.database()
}
```

### 4.2 直接复用现有 7 个云函数的函数（原样替换内部）
把以下函数内部改为 `call(...)`（删掉原来的 storage 读写实现）：

```ts
export const getList = async (params: any = {}): Promise<any> => {
  return call('getList', params)
}

export const getDetail = async (id: string): Promise<any> => {
  return call('getDetail', { id })
}

export const incrementView = async (id: string): Promise<void> => {
  await call('incrementView', { id })
}

export const addItem = async (item: any): Promise<string> => {

  return r._id
}

export const addMessage = async (msg: any): Promise<string> => {
  const r: any = await call('addMessage', msg)
  return r._id
}

export const closeItem = async (id: string): Promise<void> => {
  await call('closeItem', { id })
}

export const deleteItem = async (id: string): Promise<void> => {
  await call('deleteItem', { id })
}
```

### 4.3 统计 getStats（云端没有对应云函数）
**方案**：用 `getList({ mine: true, pageSize: 1000 })` 在前端聚合（教学/演示量级足够；若数据量大再新增 `getStats` 云函数）。
```ts
export const getStats = async (): Promise<any> => {
  const uid = '' // 云端由云函数用 OPENID 过滤，传空即可
  const mine: any = await call('getList', { mine: true, pageSize: 1000, page: 1 })
  const list = (mine.data || []) as any[]
  const open = list.filter((it) => it.status === 'open').length
  const closed = list.length - open
  return {
    total: list.length, open, closed,
    views: list.reduce((s, it) => s + (it.views || 0), 0),
  }
}
```

### 4.4 消息相关（改用新增的 getMyMessages / markRead 云函数）
```ts
export const getMessageList = async (): Promise<any[]> => {
  const r: any = await call('getMyMessages')
  return r.groups || []
}

export const getUnreadList = async (): Promise<any[]> => {
  const r: any = await call('getMyMessages')
  return (r.groups || []).map((g: any) => ({
    itemId: g.itemId, title: g.title, count: g.unreadCount,
    latestTime: g.latestTime, latestContent: g.latestContent,
  })).filter((g: any) => g.count > 0)
}

export const markItemRead = async (itemId: string): Promise<void> => {
  await call('markRead', { itemId })
}

export const markAllRead = async (): Promise<void> => {
  await call('markRead', { all: true })
}

export const refreshMsgBadge = async (): Promise<void> => {
  try {
    const r: any = await call('getMyMessages')
    const count = r.unread || 0
    if (count > 0) {
      wx.setTabBarBadge({ index: 1, text: count > 99 ? '99+' : String(count), fail: () => {} })
    } else {
      wx.removeTabBarBadge({ index: 1, fail: () => {} })
    }
  } catch (e) { /* 忽略 */ }
}
```

### 4.5 新增实时监听（watch）封装
```ts
// 监听 items 变化（首页用）
export const watchItems = (onChange: (snap: any) => void): any => {
  return cdb().collection('items').where({ status: 'open' })
    .watch({ onChange, onError: (e: any) => console.error('watch items', e) })
}

// 监听 messages 变化（消息页用）
export const watchMessages = (openid: string, onChange: (snap: any) => void): any => {
  return cdb().collection('messages')
    .where({ itemId: undefined }) // 这里用更通用写法：监听全部 messages，前端按归属过滤
    .watch({ onChange, onError: (e: any) => console.error('watch messages', e) })
}
```
> 说明：`watchMessages` 监听整张 `messages` 即可，`onChange` 里直接 `this.loadData()` 重新拉 `getMyMessages`（简单可靠）。精准监听可后续优化为按 openid 关联 items 过滤。

### 4.6 保留的本地辅助（auth、formatRelative 等）不动
`auth.getUid()` 在本地模式用于归属；云端下归属由云函数 OPENID 承担，页面中凡传 `mine:true` 即可，无需再传 uid。检查 `mine.ts` / `index.ts` 是否传了 `getUid()` 给云端函数——本改造中这些页面只调 `getList({mine:true})` 和 `getStats`，不传 uid，因此无需改动页面。

## 五、修改 miniprogram/utils/upload.ts（C）

**位置**：`uploadImage` 函数。

**改动**：把本地 `saveFile / copyFile` 三级兜底，改为 `wx.cloud.uploadFile`，返回 `cloud://` 文件 ID（云开发下 `<image src="cloud://...">` 可直接显示）。

```ts
export const uploadImage = (tempPath: string): Promise<string> => {
  const ext = (tempPath.split('.').pop() || 'png').toLowerCase()
  const cloudPath = `uploads/${Date.now()}-${Math.floor(Math.random() * 1e6)}.${ext}`
  return new Promise((resolve, reject) => {
    wx.cloud.uploadFile({
      cloudPath,
      filePath: tempPath,
      success: (r: any) => resolve(r.fileID),
      fail: (e: any) => reject(e),
    })
  })
}
```
> 注意：本地 `compressImage` 可保留（上传前压缩，节省流量）；`saveLocalFile` 可删除或保留作离线降级。

## 六、接入实时交互（D / E）

### 6.1 首页 index.ts
**位置**：`onLoad()` 末尾加监听；`onUnload()` 关闭；`data` 中加 `watcher`。

```ts
// onLoad() 末尾
this.watcher = watchItems(() => {
  this.loadData() // 数据变化即重新拉列表，实现实时刷新
})

// 新增 onUnload()
onUnload() {
  if (this.watcher && this.watcher.close) this.watcher.close()
}
```
> 顶部 import 增加 `watchItems`：`import { ..., watchItems } from '../../utils/db'`

### 6.2 消息页 messages.ts
**位置**：`onShow()` 注册监听（消息页每次显示都要刷新 + 监听）；`onHide`/`onUnload` 关闭；`data` 加 `msgWatcher`。

```ts
onShow() {
  this.loadData()
  if (this.msgWatcher && this.msgWatcher.close) this.msgWatcher.close()
  this.msgWatcher = watchMessages('', () => {
    this.loadData()
    refreshMsgBadge()
  })
}
// 关闭
onHide() { if (this.msgWatcher) this.msgWatcher.close() }
onUnload() { if (this.msgWatcher) this.msgWatcher.close() }
```
> import 增加 `watchMessages`；声明 `msgWatcher: any` 在 `data` 或类属性。

## 十、常见坑（务必注意）

1. **`_openid` 不要前端传**：云数据库文档自动带 `_openid`（创建者）；云函数内用 `OPENID`。前端 `addItem` 传的对象里**不要**带 `_openid`，否则权限校验可能异常。
2. **watch 连接数限制**：单个客户端最多 5 个 watch，记得 `onUnload` 关闭，否则真机报错/超限。
3. **数据库权限**：`items` 必须"所有人可读"否则首页看不到他人发布；写权限"仅创建者"保证安全。
4. **云函数依赖**：务必"云端安装依赖"否则 `wx-server-sdk` 未装报 `Cannot find module`。
5. **环境 ID 一致性**：`app.ts` 与 `db.ts` 的 `ENV` 必须一致且为真实环境。
6. **图片显示**：云端用 `fileID`（`cloud://`）直接作 `<image src>`，无需再 `getTempFileURL`（基础库已支持）。
7. **基础库版本**：调用方小程序基础库需 ≥ 2.2.3（云能力），watch 需更高版本（建议 ≥ 2.9.0）。
